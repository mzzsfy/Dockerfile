# 软件环境、目录映射与启动钩子

## 状态与范围

本文对应当前工作树实现，尚未发布。已增加本地行为测试及发布前 Linux 容器测试；本机没有 Docker/WSL，真实 apt、白名单重建和进程生命周期测试需在 CI 通过后才能视为已验证。不承诺立即恢复、完全离线或任意系统修改原样保留。

默认不预装语言工具链，不新增 DSH 插件，不修改用户 AGENTS.md。现有 DSH 插件首次安装仍需要网络。

## 数据卷

```sh
docker build -t dsh-local ./dsh
docker run -d --name dsh -p 3080:3080 -v dsh-home:/root dsh-local
```

复用同一个命名卷才能跨重建保留数据；一个卷只供一个活跃容器使用。整个 `/root` 内的文件持久化，其他目录须配置映射或另行挂载。原 `/root/.dsh` 卷不能直接改挂到 `/root`，数据布局不同。DSH、Node、pnpm 留在镜像中，入口优先使用镜像运行目录。

内部数据存放在 `/root/.persist/`：`tools` 保存白名单版本，`manifests` 保存 apt 目标和中断记录，`apt-cache` 保存安装包，`restore` 保存本次状态。这些文件由程序维护，不用用户编辑。

## 自定义目录映射

固定配置文件：`/root/.dsh/container/paths.txt`。每行格式为 `持久源目录:容器内目标目录`，支持空行和整行 `#` 注释。

```text
# 文件存放在主目录，通过 /data/test1 使用
/root/test1:/data/test1
/root/software/mytool:/opt/mytool
/root/software/go:/usr/local/go
```

第一行对应 `/data/test1 → /root/test1`。这是启动时创建的软链接，不是 Docker 内核挂载，无需额外权限。

规则：

- 源必须是 `/root` 下的普通目录，不能使用配置目录、内部持久化目录或它们的祖先。不存在时创建。
- 目标不能覆盖系统目录及镜像运行目录，例如 `/usr`、`/etc`、`/usr/local/bin`。允许 `/data/test1`、`/opt/mytool`、`/usr/local/go` 等独立目录。
- 源、目标必须为规范化绝对路径，不支持冒号、控制字符、尾部斜杠及 `..`。
- 目标不得重复或父子重叠；父路径不能经其他软链接绕转。
- 目标已经存在时，只接受指向该源的正确软链接。普通目录即使为空也报错，不自动搬迁、覆盖或合并。
- 使用白名单安装入口管理 Go/JDK 后，其入口不能再配置为自定义映射。
- 修改配置后重启生效。删除配置不会清理同一容器已有的链接，也不会删除源数据；新建容器不再创建该链接。需要立即撤销时，用户检查后自行删除原链接。

软件应在映射建立后安装到目标目录。若安装脚本删除并重建目标目录，它可能破坏软链接；不能保证任意安装方式都写入持久卷。目录持久化也不自动保存系统依赖。

## 固定启动钩子

两个位置固定，不需要配置脚本路径：

| 文件 | 时机 | 失败行为 |
|---|---|---|
| `/root/.dsh/container/before-start.sh` | 目录映射及白名单入口恢复后，DSH 启动前 | 停止启动 |
| `/root/.dsh/container/after-start.sh` | DSH 服务启动进程创建后 | 记录错误，保留服务 |

文件不存在则跳过；存在则用 `/bin/sh` 执行，无需可执行权限。它们会在每次启动时运行，脚本应可重复执行。

前置示例：

```sh
#!/bin/sh
set -eu
mkdir -p /data/test1/cache
```

后置示例：

```sh
#!/bin/sh
printf '%s\n' 'service process started'
```

钩子以独立子进程执行，其中 `export` 不会改变 DSH 的环境。通用环境变量通过 Docker `-e` 设置。后置钩子不表示网页健康检查通过，也不表示 apt 后台恢复完成；需要等待的脚本自行检测所需服务。钩子启动的同进程组后台进程由监督器在容器停止时清理，不支持钩子通过 `setsid` 自行脱离管理。

## 白名单工具链

提供 Go 与 JDK 的明确安装入口，接受**已经解包的 Linux 发行目录**。本轮不会捕获任意 `tar`、`curl | sh` 或源码安装。

```sh
dsh-env install go /tmp/go
dsh-env install jdk /tmp/jdk-21
```

对应关系：

| 工具 | 发行目录最低结构 | 容器入口 |
|---|---|---|
| Go | `bin/go`，执行 `go version` 成功 | `/usr/local/go` |
| JDK | `bin/java`，执行 `java -version` 成功 | `/opt/java` |

安装程序复制整个目录到新版本目录，检查目录中不存在外部绝对链接或越界链接，验证可执行文件后切换当前版本。来源不能是内部持久化目录。目标已有普通目录或其他链接时拒绝覆盖。升级执行同一安装命令，旧版本文件保留，不自动清理。

```sh
dsh-env remove go
dsh-env remove jdk
```

卸载取消当前版本和工具入口，版本文件保留在 `/root/.persist/tools/`，不会在下次启动自动复活。确认不再需要后由用户清理。

启动时恢复入口并验证运行能力；JDK 的基础依赖 `ca-certificates`、`libc6`、`libgcc-s1`、`libstdc++6`、`zlib1g` 缺失时优先通过 apt 补齐。其他发行版特有依赖、GUI/字体等功能依赖不自动推断。失败时降级启动并在状态中报告，不宣称工具就绪。首次注册工具也要求当前系统已经满足运行依赖。

入口 PATH 包含 Go/JDK 的 bin；DSH 启动时已注册 JDK 会设置 JAVA_HOME。运行中的安装命令不能改变已经存在的 DSH 进程环境：新注册 JDK 后若需要 JAVA_HOME，重启容器或给当前终端显式设置。工具版本保留，不随镜像自动升级。

Go 官方 Linux 发行目录、Temurin Linux JDK 21 目录是 CI 验证对象；只有 CI 实际通过的架构与发行组合才能作为验证依据。apt 安装的 Go/JDK/Python 不采用搬目录规则，仍由 apt 管理。

## apt 自动记录与后台恢复

正常使用：

```sh
apt-get update
apt-get install -y ripgrep python3-venv build-essential
apt-get remove -y ripgrep
```

`/usr/local/bin/apt` 与 `apt-get` 包装完整事务：取锁、读取前状态、调用真实 apt、等待退出、读取后状态、原子保存目标。没有修改系统 `/usr/bin/apt*`，也没有用 DPkg Post-Invoke 作为第二个写者。

- 镜像构建时保存基础包集合，用户新增手工安装的软件作为恢复目标。
- 保存当前目标；未恢复的软件不会被其他安装清空。正常卸载和明确取消待恢复目标会更新清单。
- 支持精确包名及 `包名:架构`。不保证复杂包模式、自定义 APT_CONFIG、改变数据库路径或绕过包装入口的操作被正确记录。
- 模拟和只下载不改变目标。失败事务保留已确认完成的变更，半配置状态不视为卸载。
- 直接 `/usr/bin/apt`、`dpkg`、`apt-mark` 的修改不属于自动记录保证。
- 软件按包名恢复，不锁定旧版本；第三方源、签名密钥、手工系统配置和用户删除基础包的意图不自动迁移。

新容器由单个后台任务恢复缺失目标，每个包重新取锁读取最新清单，避免用户卸载后按旧快照装回。恢复不改写用户目标，失败保留待恢复项。使用正常 apt/dpkg 锁，不删除锁文件。缓存减少下载，不保证断网可用。

## 中断与状态

```sh
docker exec dsh dsh-env status
docker logs dsh
```

状态输出包含 apt 恢复、白名单检查、后置脚本结果及未完成事务。`ready` 表示所声明的 apt 目标与白名单运行检查通过，不能代表任意项目都可运行；后置脚本结果单独报告。

未完成的用户 apt 事务会留下日志并暂停自动恢复，避免把不确定的卸载重新装回。检查实际系统后执行：

```sh
# 若 dpkg 提示有未配置包，先修复
/usr/bin/dpkg --configure -a
# 确认当前状态，并接受中断前明确的卸载意图
dsh-env reconcile
```

重新启动容器后重试恢复。跨重建核对不会把新容器缺少旧软件误判为已经卸载。无效配置或映射冲突停止启动，冲突目标的现有内容不被覆盖。映射按行应用，后项失败不会撤销前面已成功创建的目录和链接。

## 启动顺序

1. 创建内部目录，恢复自定义映射和白名单入口。
2. 执行固定前置脚本。
3. 完成现有插件准备，优先补齐白名单已知依赖并检查工具。
4. 创建 DSH 服务进程和单一 apt 恢复任务，执行固定后置脚本。
5. 后台恢复结束后记录结果；DSH 可以在其完成前使用。

服务退出或收到终止信号后，监督器向受管理进程组转发信号，留出退出时间后清理残留。后台安装中断不应被视为成功。网页不新增恢复进度，也不自动阻止 agent 提前运行缺失工具。

## 验收与验证

构建与以下测试命令均在仓库根目录执行。发布前容器测试当前只运行于 amd64；arm64 仅构建，尚无同等运行验收。冒烟测试覆盖映射保留、普通 apt 安装/模拟/卸载/重建、真实 Go/JDK 目录、固定钩子失败、挂起探测停止、损坏工具状态和跨重建核对；并发 apt 与真实 DSH 网页/插件健康检查仍需补充验证。下表是验收要求，不代表所有场景已执行。

本地行为测试：`node --test dsh/tests/environment.test.mjs`。Linux 容器测试：构建镜像后执行 `sh dsh/tests/smoke.sh IMAGE`；发布工作流在推送前执行测试，失败阻止该次发布。

| 场景 | 验收 |
|---|---|
| 自定义映射后写入，重建 | 目标恢复、源数据保留 |
| 映射目标已有内容 | 报错，不覆盖 |
| 前置脚本失败 | 服务不创建 |
| 后置脚本失败 | 记录失败，服务保留 |
| 普通 apt 安装后重建 | 自动恢复，真实命令可运行 |
| 模拟卸载 | 不删除恢复目标 |
| 卸载后重建 | 不复活 |
| 失败安装修复完成 | 软件被纳入目标 |
| 未完成事务后重建并核对 | 不丢失未恢复目标 |
| 白名单升级和卸载 | 原子切换或取消入口，版本数据保留 |
| 工具依赖缺失 | 不报告就绪 |
| 并发 apt 操作 | 串行化，不损坏数据库或覆盖安装意图 |
| 容器停止 | 受管理进程组退出，恢复任务不残留 |

单元测试不替代真实 Linux 的 apt/flock/信号验证。未实际运行的场景不得标记通过；跨发行版或架构的恢复需要重新验证。
